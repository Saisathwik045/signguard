# SignGuard evidence workspace

This dashboard presents the existing SignGuard project's integrity, revision,
visual-triage and security engineering. It never labels ELA/ORB as forgery
probabilities or infers signer identity from a matching mark.

## Two execution modes

- **Synthetic online workspace:** `synthetic_demo.py`, with Demo gallery,
  Project overview, Evaluation, Architecture & security, and Presentation guide.
  All five cases are historical, verified snapshots. There is no upload widget,
  parser, controller credential or execution backend in its package. Selection
  changes the displayed snapshot, not the time of analysis.
- **Private inspection:** the full project's `app.py` retains existing gateway,
  OIDC/preview authorization and broker integration. An enabled, authenticated
  private broker requests fresh analysis from the restricted executor and
  disposable worker. This mode cannot be run by the minimal online package.

Live upload controls default off. `SIGNGUARD_LIVE_UPLOADS_ENABLED=true` alone is
insufficient: the UI also requires `SIGNGUARD_REQUIRE_AUTH=true` and
`SIGNGUARD_BACKEND=broker`. These flags are configuration, not hosting attestation.
All existing deployment release gates still apply. Never use the rlimits-only
development backend to process user documents through this dashboard.

## Reading a result

The result separates signed-byte integrity, CMS mathematical validity, offline
certificate trust and identity abstention. Findings show explanations and source
evidence. Visual evidence uses the actual worker PNGs and the image fullscreen
control, with signed/current pairs when recorded. The revision timeline exposes
visible, annotation, metadata and nonvisual changes without inventing history.

The tampered-header case intentionally looks unchanged. Its signed-byte hash
fails integrity checks; a red visual box would misrepresent that evidence.
Mostly blank fixture pages are preserved faithfully. No preview is manufactured
for an unsupported document.

Use **Reports → Download JSON report / Download PDF report** for the actual
analysis files. Browser Print only exports the interface. The demo JSON bytes
match the catalogue hash; PDF downloads are the existing worker-generated bytes.
The separate **Download sample PDF** button provides the fixed input for replay
on a qualified private stack.

Processing controls for saved reports describe historical generation, not today's
Streamlit host. Missing audit receipts are explicitly unavailable. Local receipts
are not remote attestation or independently anchored evidence.

## Historical evaluation

The Evaluation page reads exact copies of the three Phase 3 summaries measured
on 2 November 2026, retaining each source path and SHA-256. It switches between
supported-only and all-case populations, displays a confusion matrix,
localization counts, errors/limitations and timing scope. No new accuracy
measurement is claimed. The holdout includes 15 false localization proposals;
the all-case alert population includes five false negatives. It is a synthetic
evaluation, not a handwriting identity or real-world accuracy claim.

## Online deployment

The standalone package is prepared for a private repository on free Streamlit
Community Cloud, Python 3.12, entrypoint `synthetic_demo.py`, `requirements.txt`,
no secrets. Verify **Only specific people can view this app** and anonymous denial
on the actual origin. Do not change audience, add a paid plan, or add arbitrary
document inputs. Free service entitlements must be checked in the account;
inactive apps can sleep. This is not an always-on promise.

To recreate the package from the full project:

```sh
PYTHONPATH=src python -m scripts.package_dashboard --output /tmp/signguard-dashboard.zip
```

Packaging copies only allowlisted synthetic data and UI files. It does not
regenerate reports, change hashes, run workers or deploy infrastructure.

## Presentation and acceptance

Follow the dashboard's seven-minute Presentation guide: explain the threat
model; compare genuine, tampered and shadow cases; discuss unsigned/visual-only
abstention; download exact evidence; compare evaluation populations; then show
fresh analysis and an unsupported-input failure only on a qualified private stack.
If that stack is unavailable, explicitly mark the final step unexecuted.

Acceptance checks: five selections, matching findings, six decoded evidence
images, exact sample/JSON/PDF bytes, navigation to every page, unsupported JSON
without a fabricated PDF, no stale report after changed input, authenticated
all-route access and denial, no unsafe parsing fallback, and unchanged forensic
source/fixtures/historical evidence.

## Remaining operational blocker

On 21 November 2026 the managed Docker daemon reports cgroup v2 but no cgroup
driver. It does not satisfy the existing rootless/systemd worker qualification.
No worker images are cached and no fresh image build/scan or all-container live
browser run is claimed for this change. Identity/TLS, actual-host isolation,
shared admission controls, durable externally anchored audit, retention,
rollback and current scans remain prerequisites for arbitrary online uploads.
No paid infrastructure or security exception is an acceptable fallback.
